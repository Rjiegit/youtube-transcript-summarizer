# 如何讓 Agent 記住規則，又不沿用過時資訊？

[回專題入口](../../../../docs/insights/topics/index.md) · 第 2 版 · 11/1–11/21 選定的 9 個來源

**把反覆要求留下來，可以減少重新交代；但保存之後，仍需要確認放在哪裡、何時適用，以及舊資訊是否該改掉。** 本次摘要把這個問題分成規則、經驗與流程三種用途，還沒有證據顯示任何一種工具能自動記對所有事情。

適合的情境是：新對話常忘記格式、同樣問題反覆糾正，或 Agent 仍沿用過時的專案習慣。這份整理討論已收錄內容的工作方式；未另行確認產品版本、功能預設或實際成效。

## 先分清楚要留下什麼

|留下的內容|整合後的用法|需要保留的界線|
|---|---|---|
|具體而穩定的規則|寫清楚可檢查的要求，例如「商品介紹不超過 50 字」。來源以專案規則檔作示範。|一次符合規則，不代表所有任務都會遵守。[M1]|
|可重複使用的流程|把反覆交代的步驟、格式及必要檢查整理成 Skill；偶發的小要求仍可直接交代。|本次不把影片描述的檔案組成當成所有工具的通用規格。[M2]|
|任務經驗與判斷理由|保存踩坑、取捨原因與使用習慣，以索引按需找到內容。|讀取、提煉與相關性判斷仍可能遺漏，保存也有計算與維護成本。[M5][M6]|

這個區分是依來源整理的使用框架，不表示三種內容永遠不能交會。例如一個反覆驗證過的經驗，可以整理成流程；但由誰決定升格、適用到哪些專案，仍要清楚說明。[M6]

## 重複的工具介紹合併看

兩支 autoharness 摘要的共同內容可合成一段：使用者糾正做法後，工具將要求整理成技能，新對話可沿用；後續補充規矩則更新原技能。無須把這個循環讀兩遍。[M3][M4]

後一支提供比較具體的案例：保存測試命名與檔案位置等三條規矩，再開新對話要求寫測試；之後補充錯誤測試規矩，原技能新增修改紀錄。這個案例值得保留，因為它讓「有記下來」變成可以實際檢查的行為。[M3]

但兩份摘要的確定度不同：一份將自動遵循寫得很肯定，另一份呈現的是特定示範。整合時採較窄的說法：**來源展示了跨對話沿用規矩的案例，尚不足以證明每次都遵守。** 這是對證據範圍的限制，並非已確認工具失效。[M3][M4]

## 前版的維護範圍

11/1 的 Skills 介紹著重將重複說明打包。11/11 的兩份記憶解說補上提煉、找回、更正，以及過期筆記和索引膨脹的維護成本。各產品的設定和架構仍須依個別資料核對。[M2][M5][M6]

## 相較前版新增的做法

前版整理了保存、回查、更正與淘汰。這週的另一支記憶解說重述筆記過期、重複和索引膨脹，主稿沿用前版的判讀。新增的是三種可操作的維護方式。

- **精簡規則後重跑固定任務。** 刪除重複、互斥與程式碼已可說明的要求，把長流程放進按需載入的 Skill。先選常做的任務和可檢查的結果，再用同一批任務比較修改前後。來源提出了比較方法，適用性仍取決於任務樣本。[M7]
- **規則散在多個專案時，保存共用版本及專案索引。** Home Repo 案例把共同規則和流程集中維護，透過各專案的路徑指引找到需要的內容。適合已經分散的儲存庫，試用時也應標明專案特例適用的位置。[M8]
- **可自動判定的重複糾正，可以寫成會執行的檢查。** Boris Cherny 的例子是把重複審查意見轉成 lint 規則。需要人解釋的決策仍適合保存理由和例外，供下次回查。[M9]

這三項是來源提出的方法和個案。摘要沒有建立同條件下的工具勝負，也沒有新證據需要撤回前版對自動整理的限制。


## 可以怎麼運用

以下是根據這些摘要提出的試用方式，尚未在本專案做成效實驗：選一條最近反覆更正的規則，寫清楚適用範圍及可檢查的結果；在新任務中觀察是否真的沿用。再檢查一條舊記憶，確認來源日期、現在是否仍成立，以及應保留、修改、刪除或整理成流程。不要只問 Agent「你記住了嗎」。

目前選材沒有建立同一條件下的可靠反例，也沒有足夠依據宣告某工具優於其他工具。自動整理可能遺漏的限制應持續保留；若未來有失敗案例，再補上具體條件。
