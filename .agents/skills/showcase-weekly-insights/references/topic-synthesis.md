# 跨影片專題整合

目標是讀完一份專題就能掌握問題，後續只需讀有價值的差異。影片 ID 去重仍用於原始來源統計；專題合併的是內容中的說法，不刪除原始摘要，也不以合併後段落數取代來源數。

## 定位與保存

- 閱讀入口：`docs/insights/topics/index.md`；專題：`apps/showcase/content/topic-readings/{topic-id}.md`。網站入口為 `/insights`，專題頁為 `/insights/topics/{topic-id}`，API 為 `/api/showcase/topics/{topic-id}`。目前沒有個人專題閱讀版本同步。
- 私人分析：`data/reports/weekly-insights/topic-digests/runs/{執行時間}/analysis.private.json`；目前狀態：`data/reports/weekly-insights/topic-digests/state.private.json`。不要改動被週報進度引用的快照。
- 沿用八個主分類；專題以穩定問題命名。同義問題沿用 ID；過廣的問題可拆成子題，記錄關係。現有 `topicTracks` 是質性演變紀錄，不等於已完成來源聚類或完整專題。較細專題以 `parentTrackId` 連到原有話題，避免偷偷更換其語意。
- 每個專題 Markdown 使用 JSON frontmatter（`---` 包住合法 JSON），保存 `topicId`、`parentTrackId`（有關聯時）、`categoryIds`、`revision`、`analysisVersion`、`updatedAt`、`coverageStart`、`coverageThrough`、`coverageMode`（`selected-sources` 或 `full-scope`）及 `sourceCount`；另填 `title`、`summary`、`relevance`、`limitation`、`changes`、`prioritySourceUrl`。`prioritySourceUrl` 必須是正文引用的 HTTPS YouTube URL；引用不同影片 URL 的去重數須等於 `sourceCount`。目前專題分析版本為 `topic-synthesis-v1`，獨立於八類主分類版本。
- 文件可提交，私人快照／分析／進度不可提交。專題連結使用整理後的原始影片 URL，不放私人服務 URL、page ID、原始全文或憑證。

## 執行流程

1. **定義範圍與基準。** 讀入口、既有專題與私人狀態，確認要處理的問題、日期、來源快照、前一版和選材範圍。優先用已核對快照；只有明確刷新或缺資料才查 Notion。週報 plan 無待辦不等於專題已完成；私人分析缺失時也不能只靠文件存在跳過。
2. **找候選，再讀正文。** 在範圍內用名稱、同義詞、摘要或相似度找候選，再完整讀取採用來源的摘要正文。關鍵詞和標題只用於選材。抽樣試作逐筆列出採用來源；其餘保留為未精讀，不能說已排除、已消除重複或計算全量重複率。一般補跑優先評估新快照與既有專題的相關候選，不自動擴成全歷史重算。
3. **以重要說法比較。** 拆出能改變理解的做法、條件、限制或證據，連回來源與摘要段落。每個說法使用穩定 `claimId`；一支影片可以同時有重複與補充，不給整支影片單一「重複／不重複」判決。
4. **標記關係與證據脈絡。** 使用下表區分關係；先確認是否談同一物件、版本、任務、時間與測試條件。相似度不能自行證明重複，措辭衝突也不必然是事實矛盾。多支轉述同一方法或發布的影片保留為同一討論脈絡；未知 channel ID 或原始出處就明記未知，不推算頻道數或獨立證據數。
5. **寫成一份可閱讀內容。** 先回答問題與適用情境，再寫合併後的原理／方法、差異與限制；來源說法和整理者的建議要能區分。每個重要結論附來源，保留反例及不確定性。選能直接幫助理解的優先來源，並交代其他來源補什麼、哪些核心介紹可略過。避免又列一串逐片摘要。
6. **更新差異而非累加文章。** 與前版的說法／證據比對；只增加來源數、改標題、換排序或同義改寫屬無實質變更。新增條件、反例、明確修正與足以改變理解的案例才更新相應段落。首版明示初次整合，不能假稱「比你上次看過新增」；來源期間內的先後比較另標日期。更正要指出原說法、修正內容與依據，不能靜默抹去。
7. **核對與保存。** 確認引用與快照吻合、分歧有保留、選材範圍誠實、閱讀稿沒有私人資訊。實質修改才增加 revision／updatedAt；無實質變更時只保存本次已評估來源與結果。先保存新的不可變私人分析，再原子替換私人狀態；單一流程寫入，失敗不登記完成。

|關係|判準與處理|
|---|---|
|`repeated`|同一適用條件下重述既有說法；合併敘述、保留引用。|
|`supplement`|補足原理、操作、案例或測試條件；加在對應段落。|
|`qualification`|限制原說法適用範圍或確定度；保留在主要結論附近。|
|`counterexample`|相同主張在特定條件下失敗的案例；寫明條件，不一般化。|
|`disagreement`|相同條件下說法不一致，尚無足夠依據判定；並列待查。|
|`correction`|有依據須撤回或修改先前版本的說法；保留更正紀錄。|

反例、分歧和更正不必每篇都有；沒有證據就明寫未建立，不湊出爭論。過度肯定的影片說法與摘要自己的保留，應呈現為確定度限制，不憑此推斷產品事實。

## 閱讀稿與私人對照

閱讀稿建議保留：一句話理解、目前整合內容、相較前版的差異（首版另述）、分歧與限制、優先來源及可略過的重複介紹。依內容調整長短，不固定字數或閱讀分鐘數。共通規則／比較適合用表格；重要限制不能全部藏在來源清單。

私人分析至少包含：

- 選材：`candidateScope`（快照、日期、候選總數）、`coverageMode`、採用來源與尚未精讀來源；數字各自有明確分母。
- 來源：`sourceKey`、原始 snapshot 路徑與 hash、來源正文／lastEditedAt 指紋；保留頁面識別於私人資料。來源後續編輯、刪除或更正時，從這裡找受影響專題；重新核對前不宣稱已驗證新版本。
- 說法：`claimId`、整理後說法、`evidence: [{sourceKey, relation, excerpt}]`。`excerpt` 是原摘要中能定位的短段落；有逐字稿時間戳才使用時間戳。同一來源的其他說法可有不同關係。
- 脈絡：已知同一工具／方法的介紹群與 `independence: unknown` 等判讀；這不是已查證的上游引用鏈。網站排名、來源數與同意票數不能替代證據品質。
- 結果：專題 ID、前後 revision、`initial`／`updated`／`no-material-change`、閱讀稿 hash、實際整理時間及未處理項目。來源只重複時仍保存本次判斷，避免下次反覆分析。

`state.private.json` 保存各專題最新閱讀稿與私人分析的路徑／hash、分析版本、已評估來源指紋與 coverageMode。只保存確認完成的範圍；選材外來源不自動視為不相關。這些紀錄目前由 agent 維護，既有 `progress.py` **不驗證專題分析**，不得把它通過說成專題語意驗證。狀態遺失或 hash 不符時先恢復／核對來源與稿件，不手改週報進度跳過。

## 與週報及網站的銜接

- 週報保存時間與主分類統計；專題保存跨影片的整合認識。單純更新專題不改週報 revision、共同 asOf 或逐週 checkpoint。
- 已核對專題可協助選近期重點，但 `series.highlights` 仍受既有比較期間及週報 sources 契約限制，不能直接塞入專題欄位或引用未列於週報的影片。
- 專題更新紀錄只比較稿件版本，目前不代表個人閱讀狀態；不批次把相關影片標成已讀。網站顯示首次整理或內容更新，不聲稱知道使用者上次看過哪版。
- 下次一般回顧先看已登記專題是否受新資料影響；明確要求「只補週報」時不擴充專題工作。未有相關新資料且未要求重整，就保留原稿日期。

## 交付前的行為檢查

- 同一方法換標題：正文不重寫；保存已評估的重複來源，無實質更新。
- 同一影片既重複又補限制：共同說法合併，限制保留；不能整支略過。
- 模擬通過與真實失敗：先對齊測試層次，不能直接合併成互相矛盾的成效。
- 新反例推翻前版：指出被修正的說法與條件，保留來源和版本。
- 只有選定來源：清楚寫試作範圍，不能宣稱全期已去重、得出全量重複率或獨立頻道數。
- 沒有新資料：不重查來源，不為了看起來有更新而改 revision／updatedAt。

完成後連到實際專題入口，回報本次合併了什麼、保留哪些新增認識，以及尚未覆蓋或查證的範圍。

## 網站 bundle 核對

`apps/showcase/content/topic-readings/manifest.json` 使用 `{ "schemaVersion": 1, "topics": [{ "id": "專題英文-slug", "published": true }] }` 選取閱讀稿；新稿先設 false，核對後才 true，此旗標只代表本機 bundle，不是遠端發布授權。未列入或未發布稿不載入。

正文保留一個 H1、可選的 `[回專題入口](../../../../docs/insights/topics/index.md)` 導覽、簡介和多個 H2；最後一個 H2 固定為「想深入時怎麼選」，其內容包含閱讀順序、重複介紹與來源對照，網站預設收合。重要限制放在簡介或正文，不能只放最後區塊。影片引用用 Markdown reference links；建置器會為各段補齊 reference definitions。僅允許 HTTPS YouTube 來源連結，不放圖片、相對檔案連結、私人網址或原始快照路徑。

閱讀稿是正文與 metadata 的單一來源，不複製到另一份網站正文。只改 metadata 格式／網站接線時，不捏造知識更新或增加內容 revision；保存新的 artifact hash 與轉換說明。正式內容有變才依流程增加 revision、updatedAt 與 changes。

驗證指令：`npm --prefix apps/showcase run insights:check`、`npm --prefix apps/showcase run test`、`npm --prefix apps/showcase run build`、`npm --prefix apps/showcase run test:ssr`。驗證器會檢查 ID、分類、日期、來源數、優先來源、連結及公開投影，但不取代摘要語意核對。啟動／建置才重新打包稿件，runtime 不讀私人快照；修改後重新啟動預覽確認卡片、正文、來源收合及 404。
